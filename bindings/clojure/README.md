# Clojure binding (generated)

`bops.clj` and `bb.edn` are generated by `bops gen clj` from `bops/commands.json`; don't edit them here. CI fails if they and the generator disagree. `bops_test.clj` is hand-written.

`bops.clj` is the namespace `bops`, with one fn per command:

- **Calls.** Each fn takes `cfg` first, which carries `:bops-path` (default `bops`) and `:actor` (passed as `BEADS_ACTOR`). Then comes the bead id if the command takes one, then the text if the command requires it (`note`), then an options map: `(bops/claim cfg "bd-a1")`, `(bops/note cfg "bd-a1" "…\n\nNEXT: …")`, `(bops/release cfg "bd-a1" {:reason "blocked" :text "BLOCKER: …"})`, `(bops/next cfg {:include-unworkable true})`.
- **Results.** Every fn returns `{:exit n :doc parsed-json :err stderr}`. Exit 3 (`lost`, `refused`) is a verdict, so it is returned, not thrown. A bad call throws before `bops` runs: a missing id, text or required option, or an option the command doesn't take.
- **Text.** Text goes on stdin. Optional text (`release`) is asked for with `--file -`, because `bops` reads stdin only when asked and babashka's `p/sh` leaves it open.
- **Schemas.** `bops/output` has a Malli schema per command, the envelope merged with the command's `output`; `bops/envelope` is the part every result carries. `(bops/valid? "claim" doc)` and `(bops/explain "claim" doc)` check a result from a run that completed (exit 0 or 3). Check an exit 1 or 2 against `bops/envelope`. Maps are open, so fields a later `bops` adds still validate.
- **Contract.** `bops/contract` is the contract it was generated for. Compare it with `(:contract (:doc (bops/version {})))`.

```bash
bb -e "(require 'bops)"      # from this directory; bb.edn adds Malli
bb bops_test.clj             # the tests; no bops needed
```

On the JVM, add `babashka/process`, `cheshire` and `metosin/malli` to your deps. The [Kestrel binding](../kestrel/) is a worked example: its policy (lint before claim, land then release, the handoff format) sits on top of this namespace.
