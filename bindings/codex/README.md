# Codex binding

`skills/bops/SKILL.md` and `hooks.json` drive the bops loop from Codex. They are generated by `bops gen codex` from `bops/commands.json`; don't edit them here. The skill's prose is `bops/internal/gen/templates/skill-preamble.md`, the same prose as the [Claude Code binding](../claude-code/), and the command reference after it comes from the manifest's `codex` surfaces. CI fails if these files and the generator disagree.

| Contract point | Mechanism | Verified |
|---|---|---|
| 1 Session start | `hooks.json`: SessionStart runs `bops session-start --hook-json` | **No.** The fragment copies upstream bd's Codex hook shape (`vendor/beads-skill/.codex-plugin/hooks/hooks.json`), and `bd codex-hook SessionStart` returns the same `hookSpecificOutput.additionalContext` envelope that `--hook-json` prints. Not yet run in Codex. |
| 2–4 Claim, note, stop | The `bops` skill | The skill is plain Markdown with frontmatter, in upstream's `.agents/skills/<name>/SKILL.md` layout. Not yet loaded by Codex. |

## Install

```bash
go install ./cmd/bops                                  # from bops/ in a beads-ops checkout
bops gen codex --out .agents                           # in your repo: .agents/skills/bops/SKILL.md and .agents/hooks.json
# in .codex/hooks.json, replace bd's SessionStart entry with the one in .agents/hooks.json, then delete .agents/hooks.json
```

Codex runs hooks only with `hooks = true` under `[features]` in `.codex/config.toml`; `bd setup codex` sets it.

Keep upstream's `PreCompact`, `PostCompact` and `UserPromptSubmit` hooks: they re-inject `bd prime` after compaction, and SessionStart's `startup|resume|clear` matcher does not fire then. Like the Claude Code binding there is no Stop hook, because a full `bops sync` pushes and takes about 3 s; the skill tells the agent to run `bops sync` before stopping.

This repo installs the skill in `.agents/skills/bops/` but leaves `.codex/hooks.json` as `bd` wrote it until the hook is verified.
