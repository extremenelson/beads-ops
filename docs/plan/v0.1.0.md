# bops — delivery plan (contract 1 → v0.1.0)

One epic, 14 tasks, each sized for a single Claude Code session, each with
acceptance criteria. Created in your ledger by `scripts/plan/v0.1.0-beads.sh`; this file is
the human-readable mirror. Numbers below are the ordering, not bead ids.

Session protocol for every task (goes in CLAUDE.md, see task 1):
`bops session-start` → `bops next` → `bops claim <id>` → work in a worktree →
tests green → commit with the bead id in the subject → `bops note` with a
`NEXT:` paragraph → `bops release --reason done` → PR.

## Tracker: beads + GitHub Issues

Beads is the execution ledger and the project's own demo; GitHub Issues is the
public surface (one issue per wave + user reports), linked by `external_ref`
and bead ids in commit subjects. No automatic sync. Nothing secret in a bead:
the Dolt data on `refs/dolt/data` is public.

## Epic: bops v0.1.0 — intent-level command layer over beads

Acceptance: `go install` or a release binary gives `next claim note release
land sweep stale lint sync session-start gates deps version` per
`SPEC.md`; Claude Code binding generated from the manifest; verified
against a live bd 1.3.x ledger; README no longer says bd is pre-1.0.

### Wave 0 — unblock everything else

1. **Verify the three unverified bd invocations on a live ledger** (P0, task)
   `bd update <id> --claim --if-assignee ''`, `bd update <id> --assignee ''`,
   `bd label add|remove <id> <label>`, plus `bd comments <id> --json` and
   `bd show <id> --json` shapes. Fix `internal/intent` + test keys if any differ.
   Acceptance: `BOPS_INTEGRATION=1` suite exists under `internal/intent`
   running `claim`/`release` against a throwaway `bd init` ledger and passes;
   `testdata/README.md` lists the verified syntaxes with bd version.

2. **Repo hygiene for the Go module** (P1, task)
   README: bd ≥ 1.3 (not "pre-1.0", "≥ 0.60"); CLAUDE.md snippet gains the
   session protocol above; `bindings/claude-code/settings.json` hooks point at
   `bops session-start` / `bops sync` instead of raw bd where bops exists.
   Acceptance: `rg "pre-1.0|0.60" README.md` is empty; hooks fragment references bops.

### Wave 1 — the rest of the agent loop

3. **`note`** (P1, task) — text via stdin/`--file` only; `bops:note run=…` event;
   W09 `NEXT:` warning; `bd heartbeat`. Blocks on 1.
   Acceptance: tests cover stdin, `--file`, refusal when run label ≠ this run,
   warning when last paragraph lacks `NEXT:`/`BLOCKER:`/`KEY DECISION:`/`REF:`.

4. **`stale`** (P1, task) — reconstruct last activity from `bd comments <id> --json`
   + `heartbeat_at`/`updated_at`; `same_machine` from run.json; `--older-than`.
   Blocks on 1. Acceptance: fixture with three claims (live, stale-same-machine,
   stale-other-machine) yields exactly the two stale ones with correct ages.

5. **`session-start`** (P1, task) — sync, `bd prime`, stale count, my in_progress,
   ready count; one compact JSON for the SessionStart hook. Blocks on 3, 4.
   Acceptance: output ≤ 1 kB for a 100-bead ledger fixture; hook fragment wired.

6. **`gates`** (P2, task) — `bd gate list --json` + blocking deps; populate
   `OpenGates` for W05 in `next`. Blocks on 1.
   Acceptance: a bead behind a human gate is excluded from `next` with `W05`.

### Wave 2 — landing and the graph

7. **Forge adapter + `land`** (P1, task) — `internal/forge` with `is_merged`,
   `ref_sha`; `github` via `gh api`, `gitlab` via `glab api`, `none`; selection
   from `git remote`. `land` writes comment + `metadata.bops.landed`.
   Acceptance: adapters tested with stubbed `gh`/`glab`; `land` never calls a forge
   unless `--verify`; metadata merge preserves foreign keys.

8. **`sweep`** (P2, task) — dry-run default; closes only beads with a merged
   `landed` ref; `--forge`. Blocks on 7.
   Acceptance: dry-run changes nothing (call log asserted); real run closes
   merged, leaves pending/unknown.

9. **`deps` (engine=bd and cte)** (P2, task) — transitive blockers/dependents,
   longest path via Kahn's algorithm in Go over `bd dep list`/`bd sql` output.
   Acceptance: 1k-node synthetic DAG fixture; critical path matches a brute-force
   oracle; cycle input returns exit 1 with the cycle named.

### Wave 3 — bindings from the manifest

10. **`cc` generator** (P1, task) — SKILL.md (hand preamble + generated reference),
    hooks fragment, optional `/bops-next` command. Golden-tested.
    Acceptance: `bops gen cc` output installs into a scratch repo and Claude Code
    lists the skill; SKILL.md ≤ 2k tokens.

11. **`clj` generator** (P2, task) — `bops.clj` shelling out, Malli schemas from
    `output`; replaces `bindings/kestrel/beads.clj`. Blocks on 10.
    Acceptance: `bb -e '(require (quote bops))'` loads; one fn per command.

12. **`mcp` generator + `bops serve-mcp`** (P3, task) — read-only tools by default,
    `--enable-writes`, 20 kB result pagination. Blocks on 10.
    Acceptance: tools list equals manifest minus writes; Claude Code connects.

### Wave 4 — ship

13. **bd 2.0 JSON envelope** (P2, task) — pin a fixture from
    `BD_JSON_ENVELOPE=1 bd ready --json`; `ledger` decodes both forms. Blocks on 1.
    Acceptance: both fixture forms decode to identical `[]Issue`.

14. **Release pipeline** (P2, task) — goreleaser (linux/darwin/windows amd64+arm64,
    android/arm64), `-ldflags -X main.version`, `go install` path in README,
    CHANGELOG entry, tag v0.1.0. Blocks on 3, 4, 5, 7, 10.
    Acceptance: a tagged build runs `bops version` on Linux x86_64 and Termux arm64.
