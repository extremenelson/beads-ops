## Implementation plan
# bops — delivery plan (contract 1 → v0.1.0)

One epic, 14 tasks, each sized for a single Claude Code session, each with
acceptance criteria. Created in your ledger by `scripts/plan/v0.1.0-beads.sh`; this file is
the human-readable mirror. Numbers below are the ordering, not bead ids.

Session protocol for every task (goes in CLAUDE.md, see task 1):
`bops session-start` → `bops next` → create a worktree → `bops claim <id>` inside it →
work → tests green → commit with the bead id in the subject → `bops note` with a
`NEXT:` paragraph → PR → `bops land` → `bops release --reason done`.
If review requests changes: `bops claim --resume <id>` (D17, D25).

## Tracker: beads + GitHub Issues

Beads is the execution ledger and the project's own demo; GitHub Issues is the
public surface (one issue per wave + user reports), linked by `external_ref`
and bead ids in commit subjects. No automatic sync. Nothing secret in a bead:
the Dolt data on `refs/dolt/data` is public.

## Epic: bops v0.1.0 — intent-level command layer over beads

gives `next claim note release land sweep stale lint sync session-start version`

the repeated two-replica concurrent-claim test never leaves an agent holding a

### Dream state delta

### Diagrams

System architecture (after D23 and D24):

```
 skill and hooks (hand-written)
        |
        v
 cmd/bops --> internal/intent --> internal/lock --> git --> refs/bops/claims/<id>   OWNERSHIP
                |     |     \--> internal/bdx --> bd --> Dolt --> refs/dolt/data    DISPLAY, best effort
                |     \--> internal/runstate: one file per clone, run id per worktree
                \--> internal/forge --> gh / glab (land, sweep)
```

Claim data flow with shadow paths:

```
 id --> bd show --> ref create --> ledger write --> claimed
         |             |                |
         |             |                +-- bd fails: still claimed, ledger_pending=true, sync retries
         |             +-- exists: lost (exit 0)
         |             +-- no network: unreachable (exit 1), no ledger write
         |             +-- forge refuses: unreachable, reason=lock_unsupported
         +-- unknown id: exit 1, no ref created
```

Bead ownership state:

```
 free --claim--> held --release(blocked|scope|stale|human)--> free
                  |  ^
                  |  +-- note refreshes the ref (held -> held)
                  +--release(done)--> landing --resume (same actor)--> held
 held or orphan --claim --force (stale only)--> held by new run
 landing --sweep after merge--> closed, ref deleted
 Refused: claim on held (lost); claim --force on landing; release by non-holder.
```

Error flow:

```
 git or bd error --> classify --> verdict (lost, refused)      exit 0, agent picks another bead
                              \-> could-not-run (unreachable)  exit 1, agent stops or retries
                              each step and outcome --> events.jsonl (D21)
```

Deployment and rollback:

```
 merge --> tag bops/v0.1.0 --> go install on machine A --> machine B
 Rollback: go install the previous tag --> delete refs/bops/claims/* --> raw bd keeps working
```

### Error and rescue registry

| Codepath | What can go wrong | Class | Rescue | Agent sees |
|---|---|---|---|---|
| `lock.Create` | Ref exists | `ErrLost` | None needed | `lost`, pick another bead |
| `lock.Create` | Network failure, no status line | `ErrUnreachable` | None; no ledger write | `unreachable`, exit 1 |
| `lock.Create` | Forge refuses custom refs | `ErrLockUnsupported` | Re-read ref to separate from a race | `unreachable`, `lock_unsupported` |
| `lock.Refresh` (`note`) | Lease lost | `ErrLost` | Drop the hold | `note` refuses |
| `lock.Refresh` (`note`) | Offline | `ErrUnreachable` | Best effort, continue | `note` succeeds with a warning |
| `lock.Delete` | Already gone | none | Treat as done | Normal outcome |
| `lock.Delete` | Network failure | `ErrUnreachable` | Retry at `sync` | `released`, `ref_pending` |
| Ledger write after claim | bd or Dolt error | `bdx.Error` | Retry at `sync` | `claimed`, `ledger_pending` |
| `claim --resume` | Actor mismatch | `ErrPrecondition` | None | `refused` |
| `sync` | Ref no longer this run's | none | Drop the hold, report | `lost_claims[]` |
| `Sync` retry | Error text contains "lock" | substring match | Pending P3 | Wrong retry |
| `sweep` ref delete | Live lock on a reopened bead | unspecified | Pending O9 | Silent |

#### Section 1: architecture

```
 cmd/bops -- emit: ok plus verdict (E15), budgets per command (E22)
    |
 internal/intent -----> internal/bdx --> bd --> Dolt  (display, best effort)
    |      |   \------> internal/forge --> gh / glab
    |      v
    |   internal/lock (NEW)  owns: journal-then-push, classify, adopt, seen refs
    |      |    \--> Git seam --> git --> refs/bops/claims/<id>   (ownership)
    |      v
    \-> internal/runstate: state.json v2, journal entries {sha, intended, phase, ...}
                           lock held only around file writes (E6)
```

Ref state and lifecycle (E1, E2):

```
 absent --create--> state=held --release(not done): delete--> absent
                     |   ^  |
                     |   |  +-- note: replace (new commit, lease)
                     |   +----- resume (same actor, lease), from landing
                     +--release(done): replace with state=landing
 state=held and stale --force, lease--> state=held (new run)
 state=landing --sweep(merged, run matches): delete with lease--> absent --> bd close
```

Sweep sequence (resolves O9):

```
 bd dolt pull  --fail--> no deletes or closes this run, report
   |
 for each in_progress bead with landed metadata and a merged PR:
   live read of ref (one ls-remote for the batch, then fetch)
   |-- absent, has bops:landing --> close (crash recovery)
   |-- absent, no bops:landing  --> pending
   |-- state=held, or run != landed.Run --> pending, touch nothing
   +-- state=landing, run matches --> delete with lease on the sha read
         |-- lease fails --> pending
         +-- deleted --> bd close --> push
```

Delete comes before close on purpose. The lease is the single point that decides between a resume and a sweep. After the delete wins, no resume can succeed, and a fresh claim is refused because the bead is still `in_progress`. Closing first could leave a closed bead with a live holder.
